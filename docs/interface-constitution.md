# ThirdSight interface constitution

ThirdSight is an evidence instrument, not a generic SaaS dashboard.

## Product rules

1. Evidence is the visual material. Prefer real integrations, fields, outcomes, timestamps, and evidence boundaries over decorative dashboard furniture.
2. Sentence case by default. Do not use uppercase eyebrows or micro-labels to manufacture hierarchy.
3. No decorative status theatre. Do not use green-dot “live”, “active”, or “online” treatments. Report a real timestamp or a real coverage gap.
4. No card unless the boundary is meaningful. A card may represent a real object, decision, evidence boundary, or contained workflow. It must not exist only to fill a grid.
5. No pill for ordinary metadata. Status should read as plain language unless a compact control genuinely needs a chip.
6. Icons are functional, not decorative. Use one only when recognition is faster than the equivalent text.
7. Do not explain the interface to the user. Remove “this page shows…”, “start with…”, and similar narration when the data itself communicates the idea.
8. Explain uncertainty and consequence. Unknown evidence, coverage gaps, prevented versus detected outcomes, and authority boundaries deserve explicit language.
9. Unknown must look unresolved. Never polish missing evidence into certainty.
10. Technical proof is progressive disclosure. The first layer is human-readable; SHOULD / COULD / DID / WHY, raw evidence, vendor docs, and analyst output sit behind evidence detail.
11. Normal activity recedes. Violations, unresolved identity, and constrained access receive the strongest hierarchy.
12. Mobile is composed separately. Do not treat it as desktop compressed into a smaller width.

## Five-second test

Hide the ThirdSight name and open the product cold.

A viewer should be able to tell, without reading a paragraph:

- which third-party integration needs attention,
- what it was approved to access,
- what was observed,
- what ThirdSight did,
- and where to inspect the proof.

If the screen could plausibly belong to HR, finance, generic DevOps, or an AI-agent dashboard after the logo is hidden, the interface is not finished.

## Evidence boundary

Presentation must never increase evidentiary authority. Vendor documentation does not become merchant approval. Browser discovery does not become complete capability. Detection does not become prevention. Missing coverage remains visible as missing coverage.
